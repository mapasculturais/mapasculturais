# Convenção 06 — i18n obrigatória em UI

Toda string exibida ao usuário passa pelo catálogo gettext via `i::__('...')` / `MapasCulturais\i::__`.

- **Catálogos**: `src/translations/` (`pt_BR` default, `en_US`, `es_ES`); negociação por header do browser com fallback `app.lcode` (`src/load-translation.php`; `config/0.main.php:36`).
- **Core/entidades**: labels e mensagens registradas usam `i::__` (ex.: roles e file groups em `App.php:3240+`, `3307+`).
- **Temas**: BaseV1 usa `_getTexts()`/`dict()` por classe de tema; BaseV2/components interpolam `i::__()` direto nos `template.php` (server-side).
- **Componentes Vue**: dicionário em `texts.php` do componente → `Mapas.gettext['component:{nome}']`, lido no JS por `Utils.getTexts('{nome}')`; hook de override `component({nome}).texts`.
- **E-mails**: templates Mustache por locale (`templates/{locale}/`, com fallback `pt_BR`) — Mustache é **somente** para e-mails; views HTML são PHP.

**Regra prática**: string crua em template/component novo = bug de i18n; commits do repo tratam isso como correção recorrente (ex.: "envolve 30 strings hardcoded em funções de tradução", git log 2026-08).
